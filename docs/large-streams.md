# Streams above 4 GiB

The manual harness in `tools/bzip2-large` generates and checks streams without
holding an entire fixture in memory. It depends only on the root codec.
Run artifacts and fixtures belong outside the repository.

## Reproduction

Build with:

```sh
cargo build --release --manifest-path tools/bzip2-large/Cargo.toml
```

Set `HARNESS` to the resulting `tools/bzip2-large/target/release/bzip2-large`
binary, `ARTIFACTS` to an external directory, and `ORACLE` to the pinned
7-Zip executable. Check available disk space first. Keeping both generated
sources and both compressed encoder variants requires about 17 GiB; reserve at
least 24 GiB. Encoding generates input directly and needs no source fixture.

```sh
"$HARNESS" generate text "$ARTIFACTS/text.txt"
"$HARNESS" generate media "$ARTIFACTS/media.wav"
ffprobe -v error -show_format -show_streams "$ARTIFACTS/media.wav"
/usr/bin/time -l "$HARNESS" encode text "$ARTIFACTS/text.bz2" 1
/usr/bin/time -l "$HARNESS" encode media "$ARTIFACTS/media.bz2" 4
/usr/bin/time -l "$HARNESS" decode text "$ARTIFACTS/text.bz2" 1
/usr/bin/time -l "$HARNESS" decode media "$ARTIFACTS/media.bz2" 4
/usr/bin/time -l "$HARNESS" raw-encode text "$ARTIFACTS/text-raw.bz2"
/usr/bin/time -l "$HARNESS" raw-encode media "$ARTIFACTS/media-raw.bz2"
/usr/bin/time -l "$HARNESS" raw-decode text "$ARTIFACTS/text-raw.bz2"
/usr/bin/time -l "$HARNESS" raw-decode media "$ARTIFACTS/media.bz2"
cmp "$ARTIFACTS/text.bz2" "$ARTIFACTS/text-raw.bz2"
cmp "$ARTIFACTS/media.bz2" "$ARTIFACTS/media-raw.bz2"
set -o pipefail
"$ORACLE" x -so "$ARTIFACTS/text.bz2" | "$HARNESS" verify text -
"$ORACLE" x -so "$ARTIFACTS/media.bz2" | "$HARNESS" verify media -
```

The commands intentionally finish the encoder and read the decoder through EOF,
validating the stream trailer. Native decode compares every output byte to a
regenerated source and checks the independent output callback total. Raw modes
check forward progress on every call, use 8,191-byte compressed buffers and
65,536-byte uncompressed buffers, and assert the final 64-bit counters. They
reject stalls and truncated input. The raw decoder also checks that it consumed
the entire encoded file.

Both sources contain exactly **4,295,032,832 bytes** (4 GiB + 65,536).
The text repeats a fixed ASCII sentence. Media is a valid RF64/WAVE container:
stereo 16-bit PCM at 48 kHz, with deterministic seeded noise samples and 64-bit
`ds64` sizes. This is synthetic audio, not a recording. High entropy makes its
compressed representation exceed 4 GiB too. Fixture generation is independent
of read chunk boundaries. No fixture bytes are committed.

## Local validation, 2026-11-05

macOS ARM64, release build, level 1, 100,000-byte blocks, one sorting pass.
The native text encoder used one thread; native media used four. The raw
encoder used one thread. ffprobe independently recognized the RF64 fixture as
`wav`, `pcm_s16le`, two channels, 48,000 Hz, duration 22,369.962250 seconds.

| Case | Input bytes | Output bytes | Maximum RSS, bytes |
| --- | ---: | ---: | ---: |
| Native text encode, ST | 4,295,032,832 | 10,064,757 | 3,391,488 |
| Raw text encode, ST | 4,295,032,832 | 10,064,757 | 3,620,864 |
| Native media encode, four threads | 4,295,032,832 | 4,329,555,102 | 8,945,664 |
| Raw media encode, ST | 4,295,032,832 | 4,329,555,102 | 4,276,224 |
| Native text decode, ST | 10,064,757 | 4,295,032,832 | 3,653,632 |
| Native media decode, four threads | 4,329,555,102 | 4,295,032,832 | 4,210,688 |
| Raw text decode, ST | 10,064,757 | 4,295,032,832 | 3,571,712 |
| Raw media decode, ST | 4,329,555,102 | 4,295,032,832 | 3,866,624 |

All listed cases passed exact regenerated byte comparisons. Native decoder
callback totals equaled 4,295,032,832. Both raw media counters exceeded
`u32::MAX` in both directions. Pinned 7-Zip independently decoded both
native streams and passed exact regenerated byte comparisons. Complete compressed
files were byte-identical between the native and raw encoders for both sources;
the media comparison covered all 4,329,555,102 compressed bytes.

RSS is the macOS `/usr/bin/time -l` maximum resident set size, in bytes,
with time wrapping the codec binary directly. Process samples also checked
actual codec child RSS. These observations are consistent with block-sized
storage rather than full-stream retention; they are not a formal memory bound.
Cases overlapped, so these runs are correctness and memory evidence, not a
throughput benchmark or performance gate.

outside Git in the external large-validation artifact directory. The repository

coverage; this manual pass specifically exercises long streams and 64-bit totals.
